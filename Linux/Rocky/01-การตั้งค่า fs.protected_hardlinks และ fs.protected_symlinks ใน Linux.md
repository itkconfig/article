# 🔐 การตั้งค่า `fs.protected_hardlinks` และ `fs.protected_symlinks` ใน Linux

การตั้งค่า `fs.protected_hardlinks` และ `fs.protected_symlinks` เป็น **Kernel Parameters** ที่ใช้เพิ่มความปลอดภัยของ Linux โดยช่วยป้องกันการโจมตีผ่าน **Hard Link** และ **Symbolic Link (Symlink)** ซึ่งอาจนำไปสู่การเขียนทับไฟล์สำคัญหรือ **Privilege Escalation**

---

## 📋 1. `fs.protected_hardlinks = 1`

ใช้สำหรับ **ป้องกัน Hard Link Attack**

### 🔴 ปัญหาเดิม

หากไม่มีการป้องกัน ผู้ใช้ทั่วไปอาจพยายามสร้าง Hard Link ไปยังไฟล์ที่ตนเองไม่ได้เป็นเจ้าของหรือไม่มีสิทธิ์เข้าถึง เช่น ไฟล์สำคัญของระบบ

ตัวอย่าง:

```bash
ln /etc/shadow /tmp/shadow
```

ระบบที่เปิดการป้องกันจะไม่อนุญาตการสร้าง Hard Link ในกรณีที่ผู้ใช้ไม่มีสิทธิ์ตามเงื่อนไขที่ kernel กำหนด

### 🛡️ เมื่อเปิดใช้งาน

```text
fs.protected_hardlinks = 1
```

Kernel จะจำกัดการสร้าง Hard Link โดยทั่วไปต้องเข้าเงื่อนไข เช่น

* ผู้ใช้เป็นเจ้าของไฟล์
* หรือผู้ใช้มีสิทธิ์ที่เพียงพอตามกฎของ kernel

ช่วยลดความเสี่ยงจากการใช้ Hard Link เพื่อโจมตีโปรแกรมที่ทำงานด้วยสิทธิ์สูง เช่น `root`

---

# 📋 2. `fs.protected_symlinks = 1`

ใช้สำหรับ **ป้องกัน Symlink Attack**

### 🔴 ปัญหาเดิม

Directory ที่ผู้ใช้หลายคนสามารถเขียนได้ เช่น:

```text
/tmp
/var/tmp
```

อาจถูกใช้โจมตีแบบ **Symlink Race Condition**

ตัวอย่างแนวคิด:

```bash
ln -s /etc/passwd /tmp/foo
```

จากนั้นหากโปรแกรมที่ทำงานด้วยสิทธิ์ `root` เขียนข้อมูลลง:

```text
/tmp/foo
```

ข้อมูลอาจถูกเขียนไปยัง:

```text
/etc/passwd
```

แทน

### 🛡️ เมื่อเปิดใช้งาน

```text
fs.protected_symlinks = 1
```

Kernel จะเพิ่มข้อจำกัดในการ Follow Symlink ใน Directory ที่มีลักษณะ **world-writable** เช่น `/tmp`

ช่วยลดความเสี่ยงจากการหลอกโปรแกรมที่มี Privileged ให้เข้าถึงไฟล์ผิดตัว

---

# 🛡️ ประโยชน์โดยรวม

การเปิดใช้งานทั้งสองค่า ช่วยเพิ่มความปลอดภัยในระดับ Kernel

### ประโยชน์หลัก

* 🔐 เพิ่มความปลอดภัยของระบบ
* 🛡️ ลดความเสี่ยงจาก Privilege Escalation
* 🚫 ป้องกัน Hard Link Abuse
* 🔗 ป้องกัน Symlink Attack
* 🏃 ลดความเสี่ยงจาก Race Condition
* 📂 เหมาะกับ Directory เช่น `/tmp` และ `/var/tmp`
* 🐧 เป็นแนวทาง Hardening ที่พบใน Linux รุ่นใหม่

---

# ⚙️ การตรวจสอบค่าปัจจุบัน

สามารถตรวจสอบได้ด้วย:

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

ตัวอย่างผลลัพธ์:

```text
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
```

หรือใช้:

```bash
sysctl -a | grep -E 'fs.protected_(hardlinks|symlinks)'
```

---

# ⚙️ การตั้งค่าแบบชั่วคราว

สามารถเปลี่ยนค่าได้ทันทีด้วย:

```bash
sudo sysctl -w fs.protected_hardlinks=1
sudo sysctl -w fs.protected_symlinks=1
```

ตรวจสอบ:

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

> ⚠️ การใช้ `sysctl -w` จะมีผลทันที แต่ค่าอาจหายหลัง Reboot หากไม่ได้บันทึกลง Configuration File

---

# 💾 การตั้งค่าแบบถาวร

สร้างไฟล์:

```bash
sudo tee /etc/sysctl.d/60-fs_sysctl.conf > /dev/null <<EOF
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
EOF
```

จากนั้นโหลด Configuration ใหม่:

```bash
sudo sysctl --system
```

ตรวจสอบ:

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

ควรได้:

```text
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
```

---

# 📁 ตำแหน่ง Configuration

ไฟล์ที่สร้างขึ้น:

```text
/etc/sysctl.d/60-fs_sysctl.conf
```

Linux จะอ่าน Configuration จากไฟล์ `sysctl.conf` และไฟล์ภายใต้:

```text
/etc/sysctl.d/
```

หมายเลข:

```text
60-
```

ช่วยกำหนดลำดับการอ่าน Configuration เมื่อมีหลายไฟล์ที่กำหนด Parameter เดียวกัน

---

# 🔍 ตรวจสอบว่าค่าถูกโหลดหลัง Reboot หรือไม่

หลังจาก Reboot:

```bash
sudo reboot
```

ตรวจสอบ:

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

หรือ:

```bash
cat /proc/sys/fs/protected_hardlinks
cat /proc/sys/fs/protected_symlinks
```

หากได้:

```text
1
1
```

แสดงว่าค่ายังคงอยู่หลัง Reboot

# ⚠️ ข้อควรระวัง

โดยทั่วไปการเปิดค่าทั้งสองเป็นการ Hardening ที่มีผลกระทบต่ำ แต่ระบบเก่าหรือ Application บางชนิดอาจพึ่งพาพฤติกรรมของ Link แบบเดิม

ควรทดสอบก่อนนำไปใช้กับ Production โดยเฉพาะ:

* Backup Software
* Legacy Application
* Custom Script
* Application ที่ใช้ `/tmp`
* Software ที่สร้าง Hard Link หรือ Symlink ในรูปแบบพิเศษ

---

# 🐳 Container

ในสภาพแวดล้อม เช่น:

```text
Docker
LXC
Container
```

Kernel Parameter บางรายการอาจถูกควบคุมโดย **Host Kernel**

ดังนั้น Container อาจไม่สามารถเปลี่ยนค่าได้เอง หรือการเปลี่ยนอาจส่งผลต่อ Host ขึ้นอยู่กับประเภทของ Container และการตั้งค่า Namespace

ตรวจสอบภายใน Container ได้ด้วย:

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

# 🔐 Recommended Configuration

สำหรับ Linux Server ทั่วไป สามารถกำหนด:

```text
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
```

แล้วโหลด:

```bash
sudo sysctl --system
```

ตรวจสอบ:

```bash
sysctl fs.protected_hardlinks fs.protected_symlinks
```

# ✅ สรุป

| Parameter                | ป้องกัน          | ค่าแนะนำ |
| ------------------------ | ---------------- | -------: |
| `fs.protected_hardlinks` | Hard Link Attack |      `1` |
| `fs.protected_symlinks`  | Symlink Attack   |      `1` |

ทั้งสองค่าเป็น **Linux Kernel Hardening Parameters** ที่ช่วยลดความเสี่ยงจากการโจมตีที่อาศัย Link ใน Directory ที่มีการเขียนร่วมกัน และช่วยลดโอกาสเกิด **Privilege Escalation**

สำหรับ Linux Server เช่น **Rocky Linux** ควรตรวจสอบค่าปัจจุบันก่อน แล้วจึงกำหนดค่าถาวรผ่าน `/etc/sysctl.d/`

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

หากยังเป็น `0` สามารถกำหนดเป็น:

```text
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
```

แล้วใช้:

```bash
sudo sysctl --system
```

เพื่อโหลดค่าทันทีโดยไม่ต้อง Reboot
