# ความแตกต่างระหว่าง `chage -d 0` และ `chage -m 0`

ก่อนอื่นต้องเข้าใจว่า `chage` ไม่ได้มีหน้าที่เปลี่ยนรหัสผ่าน แต่ใช้สำหรับ **จัดการนโยบาย (Password Aging Policy)** ที่เกี่ยวข้องกับรหัสผ่านของผู้ใช้ เช่น วันที่เปลี่ยนรหัสผ่านครั้งล่าสุด อายุขั้นต่ำ อายุสูงสุด และระยะเวลาแจ้งเตือนก่อนหมดอายุ เป็นต้น

แม้ว่าคำสั่ง `sudo chage -d 0` และ `sudo chage -m 0` จะมีเลข **0** เหมือนกัน แต่ทั้งสองคำสั่งปรับแต่ง **คนละตัวแปรในไฟล์ `/etc/shadow`** และมีวัตถุประสงค์ที่แตกต่างกันโดยสิ้นเชิง

---

## ความแตกต่างระหว่าง `chage -d 0` และ `chage -m 0`

ไฟล์ **`/etc/shadow`** เป็นไฟล์ที่เก็บข้อมูลเกี่ยวกับรหัสผ่านของผู้ใช้ รวมถึงข้อมูลด้าน **Password Aging** ซึ่งระบบ Linux ใช้ตรวจสอบว่าผู้ใช้ควรเปลี่ยนรหัสผ่านเมื่อใด และสามารถเปลี่ยนรหัสผ่านได้เมื่อไร

คำสั่งทั้งสองด้านล่างนี้จึงทำงานกับข้อมูลคนละส่วน

```bash
sudo chage -d 0 username
```

และ

```bash
sudo chage -m 0 username
```

แม้จะใช้เลข **0** เหมือนกัน แต่ผลลัพธ์แตกต่างกันอย่างมาก

---

## คำสั่ง `sudo chage -d 0`

ตัวเลือก **`-d` (Last Change Date)** ใช้กำหนด **วันที่เปลี่ยนรหัสผ่านล่าสุด (Last Password Change)**

เมื่อกำหนดเป็น

```bash
sudo chage -d 0 username
```

ระบบจะบันทึกวันที่เปลี่ยนรหัสผ่านล่าสุดเป็น **วันที่ 0** ซึ่งหมายถึง

> **1 มกราคม 1970 (Unix Epoch)**

เมื่อผู้ใช้ล็อกอินครั้งถัดไป ระบบจะคำนวณว่า

> "รหัสผ่านนี้เก่ามากและหมดอายุแล้ว"

ผลคือระบบจะบังคับให้ผู้ใช้เปลี่ยนรหัสผ่านใหม่ทันที

### ตัวอย่าง

```bash
sudo chage -d 0 student
```

เมื่อผู้ใช้ `student` ล็อกอิน

```text
WARNING: Your password has expired.
You must change your password now.
```

ผู้ใช้จะไม่สามารถใช้งาน Shell ได้จนกว่าจะเปลี่ยนรหัสผ่านสำเร็จ

---

## คำสั่ง `sudo chage -m 0`

ตัวเลือก **`-m` (Minimum Age)** ใช้กำหนด

> จำนวนวันขั้นต่ำที่ต้องรอก่อนจะสามารถเปลี่ยนรหัสผ่านใหม่ได้

ตัวอย่าง

```bash
sudo chage -m 7 username
```

หมายความว่า

หลังจากเปลี่ยนรหัสผ่านแล้ว ต้องรอ **7 วัน** จึงจะสามารถเปลี่ยนอีกครั้งได้

นโยบายนี้ช่วยป้องกันไม่ให้ผู้ใช้เปลี่ยนรหัสผ่านหลายครั้งติดกันเพื่อย้อนกลับไปใช้รหัสผ่านเดิม

แต่เมื่อกำหนดเป็น

```bash
sudo chage -m 0 username
```

หมายถึง

**ไม่มีระยะเวลาขั้นต่ำ**

ผู้ใช้สามารถเปลี่ยนรหัสผ่านได้ทันทีเมื่อใดก็ได้

ตัวอย่าง

```text
09:00 เปลี่ยนรหัสผ่านครั้งที่ 1

09:05 เปลี่ยนใหม่อีกครั้ง

09:10 เปลี่ยนอีกครั้ง
```

ระบบจะอนุญาตทั้งหมด

# เปรียบเทียบความแตกต่าง

## `chage -d 0`

**เปลี่ยนค่า**

- Last Password Change

**ผลลัพธ์**

- บังคับให้รหัสผ่านหมดอายุทันที
- ผู้ใช้ต้องเปลี่ยนรหัสผ่านในการล็อกอินครั้งถัดไป

**เหมาะสำหรับ**

- สร้างบัญชีผู้ใช้ใหม่
- รีเซ็ตรหัสผ่านให้ผู้ใช้
- บังคับให้ผู้ใช้ตั้งรหัสผ่านด้วยตนเอง

**ตัวอย่าง**

```bash
sudo passwd student
sudo chage -d 0 student
```

---

## `chage -m 0`

**เปลี่ยนค่า**

- Minimum Password Age

**ผลลัพธ์**

- อนุญาตให้เปลี่ยนรหัสผ่านได้ทุกเวลา
- ไม่ได้บังคับให้เปลี่ยนรหัสผ่าน

**เหมาะสำหรับ**

- ระบบที่ไม่ต้องการจำกัดความถี่ในการเปลี่ยนรหัสผ่าน
- ช่วงทดสอบระบบ
- การรีเซ็ตรหัสผ่านหลายครั้งในวันเดียว

**ตัวอย่าง**

```bash
sudo chage -m 0 student
```

---

# ตรวจสอบค่าปัจจุบัน

สามารถดูค่าทั้งหมดได้ด้วย

```bash
sudo chage -l student
```

ตัวอย่างผลลัพธ์

```text
Last password change                                    : Sep 06, 2026
Password expires                                        : never
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 99999
Number of days of warning before password expires       : 7
```

สังเกตว่า

- **Last password change** คือค่าที่ถูกกำหนดด้วย `-d`
- **Minimum number of days between password change** คือค่าที่ถูกกำหนดด้วย `-m`

---

# สรุป

แม้ว่าคำสั่ง `sudo chage -d 0` และ `sudo chage -m 0` จะใช้เลข **0** เหมือนกัน แต่ทั้งสองคำสั่งทำงานกับ **คนละพารามิเตอร์ในไฟล์ `/etc/shadow`** และมีวัตถุประสงค์ที่แตกต่างกันอย่างชัดเจน

- `sudo chage -d 0` ใช้ปรับค่า **Last Password Change** ให้เป็นวันที่ **1 มกราคม 1970 (Unix Epoch)** เพื่อทำให้ระบบมองว่ารหัสผ่านหมดอายุ และ **บังคับให้ผู้ใช้เปลี่ยนรหัสผ่านในการเข้าสู่ระบบครั้งถัดไป**
- `sudo chage -m 0` ใช้กำหนดค่า **Minimum Password Age** เป็น **0 วัน** ทำให้ **ผู้ใช้สามารถเปลี่ยนรหัสผ่านได้ตลอดเวลา** โดยไม่ต้องรอระยะเวลาขั้นต่ำหลังจากการเปลี่ยนครั้งก่อน

ดังนั้น หากผู้ดูแลระบบต้องการ **บังคับให้ผู้ใช้เปลี่ยนรหัสผ่านหลังจากรีเซ็ตหรือสร้างบัญชีใหม่** ควรใช้ `chage -d 0` ส่วน `chage -m 0` ใช้สำหรับ **ปรับนโยบายการเปลี่ยนรหัสผ่าน** และ **ไม่ได้ทำให้รหัสผ่านหมดอายุหรือบังคับให้ผู้ใช้เปลี่ยนรหัสผ่านแต่อย่างใด**
