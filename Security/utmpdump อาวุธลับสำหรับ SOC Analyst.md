**เจาะลึกคำสั่ง `utmpdump`: อาวุธลับสำหรับ SOC Analyst ในงาน Forensics และ Threat Hunting**
**ยู-เทมป์-ดัมพ์ (U-temp-dump) - เป็นการอ่านแบบรวบคำ ซึ่งพบได้บ่อยที่สุด**

**ยู-ที-เอ็ม-พี-ดัมพ์ (U-T-M-P-dump) - เป็นการอ่านแบบเรียงทีละตัวอักษร**

สำหรับผู้ปฏิบัติงานใน Security Operations Center (SOC) หรือทีม Incident Response (IR) เมื่อต้องสืบสวนเหตุการณ์บนระบบปฏิบัติการ Linux การตรวจสอบประวัติการ Login เป็นสิ่งแรกๆ ที่ต้องทำ โดยปกติเรามักจะคุ้นเคยกับคำสั่ง `last`, `lastb` หรือ `who` แต่เครื่องมือเหล่านั้นเป็นเพียงการนำเสนอข้อมูลในรูปแบบที่ "อ่านง่าย" (Human-readable) ซึ่งอาจซ่อนรายละเอียดสำคัญบางอย่างไว้

ในบทความนี้ เราจะเจาะลึกคำสั่ง **`utmpdump`** ซึ่งเป็นเครื่องมือระดับ Raw-level ที่แสดงโครงสร้างข้อมูลดิบของการ Login และเป็นทั้ง **"เครื่องมือสืบสวนชั้นยอด"** และ **"เครื่องมือลบร่องรอยของแฮกเกอร์"** (Anti-Forensics) ในเวลาเดียวกัน

---

### 1. ทำความเข้าใจเป้าหมายของ `utmpdump`

ระบบ Linux บันทึกข้อมูลการเข้าสู่ระบบไว้ในไฟล์ไบนารี (Binary Files) 3 ไฟล์หลัก ซึ่งไม่สามารถใช้คำสั่ง `cat` เปิดอ่านได้โดยตรง:
*   `/var/run/utmp` (หรือ `/run/utmp`): บันทึกผู้ใช้ที่กำลัง Login อยู่ ณ ปัจจุบัน
*   `/var/log/wtmp`: บันทึกประวัติการ Login/Logout, การ Reboot และ Shutdown
*   `/var/log/btmp`: บันทึกประวัติการ Login ที่ล้มเหลว (Failed Login Attempts)

คำสั่ง `utmpdump` ทำหน้าที่ **แปลงไฟล์ไบนารีเหล่านี้ให้ออกมาเป็นข้อความ (Plain Text)** แบบละเอียดทุกฟิลด์ และในทางกลับกัน สามารถ **แปลงข้อความกลับไปเป็นไฟล์ไบนารีได้ (`-r`)**

---

### 2. โครงสร้างข้อมูลดิบ (The Raw Data Structure)

เมื่อคุณรันคำสั่ง `utmpdump /var/log/wtmp` ผลลัพธ์ที่ได้จะอยู่ในรูปแบบนี้:

```text
[7] [01234] [ts/0] [root] [pts/0] [192.168.1.100] [192.168.1.100] [2023-10-27T10:15:30,000000+00:00]
```

สำหรับ SOC Analyst คุณต้องถอดรหัสฟิลด์ในวงเล็บเหลี่ยมให้เป็น ดังนี้:
1.  **[Type]**: ชนิดของ Record (สำคัญมากสำหรับการทำ Forensics)
    *   `[2]` = BOOT_TIME (ระบบเพิ่งบูต)
    *   `[7]` = USER_PROCESS (มีผู้ใช้ Login เข้ามาสำเร็จ)
    *   `[8]` = DEAD_PROCESS (กระบวนการสิ้นสุดลง หรือผู้ใช้ Logout)
2.  **[PID]**: Process ID ของเซสชันนั้น
3.  **[Line]**: ชื่อ Terminal หรือ TTY (เช่น pts/0, tty1)
4.  **[ID]**: Terminal ID หรือ Init ID
5.  **[User]**: ชื่อ Username ที่ใช้ Login
6.  **[Host]**: ชื่อโฮสต์ปลายทาง (มักเป็นช่องว่าง หากไม่ได้มาจาก X window)
7.  **[IP]**: หมายเลข IP Address ของผู้ที่เชื่อมต่อเข้ามา
8.  **[Timestamp]**: เวลาที่เกิดเหตุการณ์แบบ Microsecond (แม่นยำกว่าการดูด้วยคำสั่ง `last` มาก)

### 3. กรณีศึกษาสำหรับ SOC (Use Cases in Investigations)

#### Case 1: การตรวจจับ Brute Force ระดับลึก (`btmp`)
คำสั่ง `lastb` อาจบอกคุณได้ว่ามีการเดารหัสผ่านล้มเหลว แต่มันไม่ได้ให้รูปแบบ Raw Data ที่ง่ายต่อการนำไปเขียน Script วิเคราะห์ต่อ SOC Analyst สามารถใช้ `utmpdump` ดึงเฉพาะ IP ที่โจมตีออกมานับจำนวนได้ง่ายๆ:
```bash
utmpdump /var/log/btmp 2>/dev/null | awk '{print $7}' | sort | uniq -c | sort -nr
```
*เทคนิคนี้ช่วยให้เราเห็น Top Attackers IPs เพื่อนำไปบล็อกบน Firewall หรือส่งต่อให้ Threat Intelligence*

#### Case 2: การวิเคราะห์ Lateral Movement และ Session Hijacking
เนื่องจาก `utmpdump` แสดง Timestamp ในระดับ **ไมโครวินาที (Microsecond)** หากคุณสงสัยว่ามีการขโมยเซสชัน หรือมีสคริปต์อัตโนมัติ (Malware/Worm) กระจายตัวข้ามเครื่อง คุณสามารถเปรียบเทียบความห่างของเวลา [Timestamp] ระหว่าง Type `[7]` (Login) กับ Type `[8]` (Logout) หากพบว่าเซสชันถูกเปิดและปิดในเวลาเสี้ยววินาทีซ้ำๆ อาจบ่งบอกถึงพฤติกรรมของ Automated Script ไม่ใช่มนุษย์

#### Case 3: การตรวจจับพฤติกรรม Anti-Forensics (การลบ Log)
นี่คือจุดที่ `utmpdump` สำคัญที่สุดในมุมมองของนักสืบสวน! 
แฮกเกอร์ที่เก่งจะไม่ลบไฟล์ `/var/log/wtmp` ทิ้งทั้งไฟล์ หรือทำไฟล์ให้ว่างเปล่า (`echo "" > /var/log/wtmp`) เพราะระบบ Monitoring ของ SOC จะแจ้งเตือนไฟล์ผิดปกติทันที สิ่งที่แฮกเกอร์ทำคือการ "แก้ไขเฉพาะบรรทัดของตัวเอง" โดยใช้ `utmpdump`:

**สิ่งที่แฮกเกอร์ทำ:**
1. แปลงไฟล์ไบนารีเป็น Text: `utmpdump /var/log/wtmp > dummy.txt`
2. ลบประวัติ IP ตัวเองทิ้ง: `sed -i '/10.10.99.100/d' dummy.txt`
3. **ใช้ `utmpdump` แปลงกลับเป็นไบนารี:** `utmpdump -r dummy.txt > /var/log/wtmp`

**วิธีที่ SOC ตรวจจับการกระทำนี้:**
*   **ตรวจสอบ Inode และ Timestamps:** หากไฟล์ `wtmp` ถูกเขียนทับด้วยวิธีนี้ ค่า Change Time (ctime) และ Modify Time (mtime) ของไฟล์ `/var/log/wtmp` จะเปลี่ยนไปแบบผิดธรรมชาติ
*   **Cross-Correlation (หาจุดขัดแย้ง):** SOC ต้องนำข้อมูลจาก `utmpdump` ไปเทียบกับ `/var/log/secure` หรือ `/var/log/auth.log` (ซึ่งจัดการโดย `rsyslog` และเป็น Plain text) หากแฮกเกอร์ลบข้อมูลใน `wtmp` แต่ลืมลบใน `auth.log` คุณจะเห็นรอยโหว่ (Gap) ทันทีว่ามีคนล็อกอินใน `auth.log` แต่ไม่มีประวัติใน `wtmp`

### บทสรุปสำหรับนักวิเคราะห์ความปลอดภัย

`utmpdump` ไม่ใช่แค่เครื่องมือแปลงไฟล์ แต่เป็นแว่นขยายที่ช่วยให้ SOC Analyst เห็นโครงสร้างข้อมูลดิบของการเข้าถึงระบบ เมื่อเกิดเหตุการณ์ละเมิดความปลอดภัย การพึ่งพาคำสั่ง `last` เพียงอย่างเดียวอาจทำให้คุณตกหลุมพรางของแฮกเกอร์ที่แก้ไขไฟล์ไบนารีไปแล้ว การดึงข้อมูลด้วย `utmpdump` ออกมาวิเคราะห์ร่วมกับ Log ระบบอื่นๆ จะช่วยยืนยันความถูกต้องของไทม์ไลน์และเปิดโปงพฤติกรรมซ่อนพรางได้อย่างแม่นยำครับ

**ข้อควรระวัง:** เวลาใช้ `utmpdump` กับไฟล์ `btmp` ที่มีขนาดใหญ่มากๆ (จากการโดน Brute Force เป็นล้านครั้ง) ควร Pipe ส่งไปที่ `less` หรือ `grep` เสมอ เพื่อป้องกันไม่ให้ Terminal ค้างครับ
