# 🛠️ คู่มือ 10 สิ่งที่ควรทำทันทีหลังติดตั้ง Proxmox VE 9 (Post-Installation Guide)

บทความนี้เรียบเรียงขึ้นจากคำแนะนำและเทคนิคการตั้งค่าจากแหล่งข้อมูล **"10 Things You Should Do After Installing Proxmox VE 9"** [1] เพื่อเตรียมระบบโฮสต์ของคุณให้มีประสิทธิภาพสูงสุด เสถียร และปลอดภัยสำหรับการใช้งานใน Home Lab หรือระบบงานจำลองระดับองค์กร

---

## 📋 สรุป 10 ขั้นตอนการเพิ่มประสิทธิภาพและความปลอดภัย

### 1. 🧹 เคลียร์ฮาร์ดดิสก์สำรองเพื่อเตรียมใช้งาน (Wipe Secondary Disk)
หากคุณมีฮาร์ดดิสก์ตัวที่สอง (เช่น NVMe SSD หรือ HDD ขนาด 1 TB) ที่จะนำมาใช้เก็บข้อมูล VMs/Containers ควรทำความสะอาดไดรฟ์นั้นให้หมดจดเสียก่อน [2]
* **วิธีทำผ่าน GUI:** [3]
  1. ไปที่ชื่อโหนด Proxmox ของคุณ (เช่น `PVE0`) [2, 3]
  2. เลือกเมนู **Disks** [3]
  3. เลือกไดรฟ์ที่ต้องการล้างข้อมูล (เช่น `/dev/nvme0n1` หรือ `/dev/sda`) [2, 3]
  4. คลิกปุ่ม **Wipe Disk** แล้วตอบตกลง (**Yes**) [3]
  > ⚠️ *ข้อควรระวัง: ขั้นตอนนี้จะลบข้อมูลทั้งหมดในดิสก์ดังกล่าวอย่างถาวร โปรดตรวจสอบให้มั่นใจก่อนกดล้างข้อมูล [3]*

---

### 2. 🌐 ตั้งค่า DNS สำรองเพื่อความเสถียร (Configure DNS Servers)
ระบบโดเมนหรือ DNS มักมีโอกาสขัดข้องได้ง่าย การเพิ่มผู้ให้บริการ DNS สาธารณะที่น่าเชื่อถือจะช่วยให้ระบบสามารถดึงข้อมูลแพ็กเกจและอัปเดตต่างๆ ได้ตลอดเวลา [3]
* **วิธีทำผ่าน GUI:** [3, 4]
  1. ไปที่โหนด Proxmox -> เมนู **System** -> **DNS** [3]
  2. คลิก **Edit** [3]
  3. เพิ่มค่า DNS สำรองของ Cloudflare และ Google: [4]
     * **First DNS Server:** `1.1.1.1` [4]
     * **Second DNS Server:** `8.8.8.8` [4]
  4. คลิก **OK** [4]

### 3. 📦 ปิด Enterprise Repositories และเปิดใช้งาน No-Subscription แทน
โดยค่าเริ่มต้น Proxmox จะตั้งค่าให้ดึงข้อมูลอัปเดตจาก Enterprise Repo ซึ่งจำเป็นต้องมีสิทธิ์ไลเซนส์แบบชำระเงิน หากคุณไม่มีไลเซนส์ การสั่งอัปเดตจะล้มเหลว (Failed) [4]
* **วิธีทำผ่าน GUI:** [4]
  1. ไปที่โหนดของคุณ -> เมนู **Updates** -> **Repositories** [4]
  2. คลิกเลือกรายการที่เป็น Enterprise (เช่น `pve-enterprise` และ `ceph` ระดับองค์กร) แล้วกด **Disable** [4]
  3. คลิกปุ่ม **Add** -> เลือกทางเลือก **No-Subscription** เพื่อใช้พื้นที่เก็บข้อมูลแพ็กเกจฟรี จากนั้นคลิกตกลง [4]

### 4. 🚀 ทำการอัปเดตและอัปเกรดระบบ (Update & Upgrade System)
หลังจากเปลี่ยนการตั้งค่า Repository เรียบร้อยแล้ว ให้ทำการอัปเกรดซอฟต์แวร์ระบบเป็นเวอร์ชันล่าสุดเพื่อรับแพตช์ความปลอดภัยและประสิทธิภาพสูงสุด [5]
* **คำสั่งรันผ่าน SSH หรือ Console:** [5]
  ```bash
  # อัปเดตและอัปเกรดระบบแบบข้ามการถามยืนยัน (-y)
  apt update && apt upgrade -y
  ```
  เมื่อเสร็จสิ้นให้ทำการรีบูตระบบเพื่อให้ระบบนำเคอร์เนลล่าสุดมาใช้: [6]
  ```bash
  reboot
  ```

### 5. 🔌 เปิดใช้งาน IOMMU สำหรับทำ PCIe Passthrough
เพื่อให้สามารถส่งผ่านฮาร์ดแวร์จริง เช่น การ์ดจอ (GPU), การ์ดเครือข่าย หรือดิสก์คอนโทรลเลอร์ ตรงไปยัง Virtual Machine (VM) โดยไม่ผ่านเลเยอร์จำลอง [8]
1. ตรวจสอบประเภท Bootloader ของคุณ (Grub หรือ Systemd-boot): [8]
   * หากมีคำตอบแสดงผลออกมาเกี่ยวกับ Grub ให้ทำตามขั้นตอนถัดไป [8]
2. แก้ไขไฟล์การบูต Grub: [8]
   ```bash
   nano /etc/default/grub
   ```
   หาบรรทัด `GRUB_CMDLINE_LINUX_DEFAULT="quiet"` แล้วใส่เครื่องหมาย `#` ด้านหน้าเพื่อข้ามการทำงานเดิม หรือทำการแก้ไขบรรทัดคำสั่งโดยระบุพารามิเตอร์ดังนี้: [8]
   * **สำหรับ Intel CPU:** [9]
     ```bash
     intel_iommu=on iommu=pt
     ```
   * **สำหรับ AMD CPU:** (ผู้สอนระบุพารามิเตอร์ที่เหมาะสมสำหรับ AMD ไว้ที่เว็บเพิ่มเติม) [9]
3. สั่งอัปเดต Grub เพื่อบันทึกค่าลงบูตเซกเตอร์: [9]
   ```bash
   update-grub
   ```
4. เพิ่มโมดูลระบบลงในไฟล์คอนฟิก `/etc/modules`: [9]
   ```bash
   nano /etc/modules
   ```
   เพิ่ม 3 บรรทัดนี้ลงด้านล่างสุดของไฟล์: [9]
   ```text
   vfio
   vfio_iommu_type1
   vfio_pci
   ```
5. สั่งรีบูตเครื่อง (`reboot`) จากนั้นล็อกอินกลับเข้ามาแล้วตรวจสอบผลลัพธ์ด้วยคำสั่ง: [9, 10]
   ```bash
   # ตรวจสอบการเปิดใช้งาน IOMMU จาก Kernel Log
   dmesg | grep -e DMAR -e IOMMU
   
   # นับจำนวนกลุ่ม IOMMU (ควรได้ค่ามากกว่า 0)
   ls /sys/kernel/iommu_groups/ | wc -l
   
   # ยืนยันว่าโมดูลทำงานครบถ้วน
   lsmod | grep vfio
   ```
   *(หมายเหตุ: ใน Proxmox 9 มีโมดูลหลักที่ต้องโหลดเพียง 3 ตัว ต่างจากเวอร์ชันก่อนหน้าที่ต้องใช้ 4 ตัว)* [9]

### 6. 🖧 เปิดใช้งาน VLAN Aware บน Network Bridge
การตั้งค่าบริดจ์เครือข่ายให้รองรับ VLAN (Virtual LAN) ช่วยให้คุณแยกและควบคุมทราฟฟิกของแต่ละ VM ให้อยู่ในเซกเมนต์ความปลอดภัยที่แตกต่างกันได้โดยตรงจาก GUI ของ Proxmox [12]
* **วิธีทำผ่าน GUI:** [12]
  1. ไปที่โหนด Proxmox -> **System** -> **Network** [12]
  2. เลือกเครือข่ายหลัก `vmbr0` แล้วคลิก **Edit** [12]
  3. ติ๊กเครื่องหมายถูกที่ช่อง **VLAN Aware** แล้วคลิก **OK** [12]
  4. คลิกปุ่ม **Apply Changes** ด้านบนเพื่อเริ่มใช้งานทันที [12]
* **คำสั่งยืนยันผลลัพธ์ใน Terminal:** [12]
  ```bash
  # ตรวจสอบว่ามีค่า bridge-vlan-aware yes อยู่ในอินเตอร์เฟส
  cat /etc/network/interfaces
  ```

### 7. 🗄️ เชื่อมต่อ Network Storage เพื่อเก็บข้อมูลสำรอง (NFS/SMB)
เพื่อความสะดวกในการจัดการทรัพยากรบนหลายโหนด (Cluster) การเก็บไฟล์ติดตั้งระบบปฏิบัติการ (ISOs) หรือข้อมูลสำรองใน Network Storage เช่น NFS Share เป็นสิ่งจำเป็นมาก [13]
* **วิธีทำผ่าน GUI:** [14]
  1. ไปที่เมนู **Datacenter** -> **Storage** -> คลิกปุ่ม **Add** -> เลือก **NFS** (หรือ SMB ตามประเภทสตอเรจของคุณ) [14]
  2. ระบุค่าข้อมูล: [14]
     * **ID:** `vault` (หรือชื่ออื่นๆ ตามต้องการ) [14]
     * **Server:** [ระบุ IP ของ Storage Server เช่น `10.100.1.220`] [14]
     * **Export:** เลือกตำแหน่ง Mount Array ของสตอเรจปลายทาง [14]
     * **Content:** ทำการดึงข้อมูลและเลือกเก็บประเภทไฟล์ได้แก่ `Container templates`, `ISO images`, `VZTmpl` (Container Templates), `Backups` และ `Snippets` [14, 15]
  3. คลิก **Add** [15]
* **คำสั่งตรวจสอบและทดสอบสิทธิ์การเขียนข้อมูล:** [15]
  ```bash
  # ตรวจสอบสถานะและพื้นที่ว่างของ Storage ด้วยคำสั่ง Proxmox Volume Manager
  pvesm status
  
  # ทดสอบสิทธิ์เขียนไฟล์โดยสร้างไฟล์จำลองลงตำแหน่ง Mount point
  touch /mnt/pve/vault/write_test && echo "Write OK" && rm /mnt/pve/vault/write_test
  ```

### 8. 🔕 ปิดการแจ้งเตือนล็อกอิน "No Subscription" กวนใจ
เมื่อล็อกอินเข้าใช้งาน Proxmox เวอร์ชันฟรี คุณจะได้รับการแจ้งเตือนแสดงข้อความสิทธิ์ไม่มีสิทธิ์ใช้งาน (No Subscription) ทุกครั้ง วิธีการแก้ไขให้ไม่แสดงข้อความนี้คือการดัดแปลงสถานะในไฟล์ JavaScript หลัก [16]
* **ขั้นตอนและคำสั่งในการทำ:** [16, 17, 18]
  1. ทำการสำรองไฟล์ต้นฉบับก่อนเพื่อความปลอดภัย: [17]
     ```bash
     cp /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js.bak
     ```
  2. ตรวจสอบตำแหน่งข้อความแสดงผล (ปกติจะอยู่ในฟังก์ชันตรวจสอบสิทธิ์ที่พบบรรทัดคำว่า `.status.toLowerCase() === 'active'`): [17, 18]
     ```bash
     # ค้นหาคำที่เข้าข่ายเพื่อตรวจสอบตำแหน่งบรรทัด (เช่น บรรทัดที่ 624)
     grep -n "status.toLowerCase() === 'active'" /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js
     ```
  3. ใช้คำสั่งแก้ไขหรือเปิดแก้ไขไฟล์ด้วย `nano` เพื่อเปลี่ยนสถานะการตรวจสอบเงื่อนไขจาก `'active'` เป็น `'false'` (เพื่อให้สคริปต์มองข้าม): [18]
     ```bash
     # สั่งแก้ไขโดยตรงผ่าน sed เพื่อเปลี่ยนค่าเป็น false
     sed -i 's/res.data.status.toLowerCase() === \x27active\x27/res.data.status.toLowerCase() === \x27false\x27/g' /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js
     ```
  4. ทำการรีสตาร์ทเซอร์วิสเว็บเซิร์ฟเวอร์เพื่อให้การแก้ไขมีผล: [18]
     ```bash
     systemctl restart pveproxy
     ```
  5. เคลียร์แคชเบราว์เซอร์อย่างสมบูรณ์โดยการกดปุ่ม `Ctrl + Shift + R` บนคีย์บอร์ดแล้วลองล็อกอินใหม่อีกครั้ง [19]

### 9. 💾 ตั้งค่า ZFS VM Data Pool พร้อมจำกัดการใช้งาน RAM ของ ARC
ZFS มีจุดเด่นด้านเสถียรภาพและการปกป้องข้อมูล แต่มีความต้องการการใช้งานหน่วยความจำสูงมาก หากคุณไม่ได้ปรับตั้งค่าไว้ มันอาจเข้าครอบครอง RAM ระบบไปเป็นจำนวนมาก (สูงสุด 50%) [19, 21]
1. **สร้าง ZFS Pool บน GUI:** ไปที่โหนด -> **ZFS** -> **Create: ZFS** ตั้งชื่อสตอเรจว่า `VM_data` (แนะนำให้ใช้ชื่อเดียวกันในทุกโหนดหากจะทำ Cluster ในอนาคตเพื่อให้อ้างอิงพาธตรงกันได้สะดวกเวลาโยกย้าย VM) เลือกดิสก์ตัวที่สองที่เคลียร์เตรียมไว้ ตั้งค่า Compression: on, Ashift: 12 แล้วกดสร้าง [20, 21]
2. **จำกัดขนาดหน่วยความจำสูงสุดของ ZFS ARC (Adaptive Replacement Cache):** [21]
   * *สูตรแนะนำ:* สำหรับระบบ RAM 16GB ควรจำกัด ARC ไว้ที่ 2GB (หาก RAM 32GB แนะนำ 4GB) [21]
   * คำนวณค่าขนาดเป็นไบต์ (Bytes):
     * 2 GB = `2147483648` Bytes [21]
   * เขียนพารามิเตอร์กำหนดขอบเขต RAM ลงไฟล์คอนฟิก ZFS: [21]
     ```bash
     echo "options zfs zfs_arc_max=2147483648" > /etc/modprobe.d/zfs.conf
     ```
3. **รีบิวด์แพ็กเกจบูต Kernel และรีบูตโฮสต์:** [21, 22]
   ```bash
   update-initramfs -u -k all
   reboot
   ```
4. **ตรวจสอบสถานะการจำกัดขนาดแคชหลังบูตระบบขึ้นมาใหม่:** [22]
   ```bash
   # ตรวจสอบสถานะความสมบูรณ์ของ ZFS pool
   zpool status
   
   # ตรวจสอบขนาดสูงสุดของ ARC Cache ในระบบจริง (ควรเห็นค่าประมาณ 2 GB)
   arcstat
   ```

### 10. 🛡️ ติดตั้งและตั้งค่า Fail2Ban ป้องกันภัยคุกคามและการเดารหัสผ่าน
เพื่อป้องกันผู้ไม่หวังดี เครื่องคอมพิวเตอร์ที่ติดมัลแวร์ หรืออุปกรณ์ IoT ที่พยายามล็อกอินและเดารหัสผ่าน Server ของคุณ หากทำผิดพลาดเกินจำนวนกำหนดจะบล็อก IP ทันที [23]
1. **ติดตั้งโปรแกรมและไลบรารีที่จำเป็น:** [23]
   ```bash
   apt install fail2ban python3-systemd -y
   ```
2. **สร้างกฎกรอง Log ล็อกอิน Proxmox (Proxmox Filter):** [24]
   ```bash
   nano /etc/fail2ban/filter.d/proxmox.conf
   ```
   *ระบุรายละเอียดแพตเทิร์นดักจับล็อกอินล้มเหลว (Regex) ลงในไฟล์นี้:* [24]
   ```text
   [Definition]
   # กรอกเงื่อนไขตัวกรองจับ Log ที่ผิดพลาดจาก pvedaemon ตามแพตเทิร์นของ Proxmox 9
   # (สามารถคัดลอก Regex สำหรับ Proxmox 9 เพิ่มเติมเพื่อดักจับล็อกอินล้มเหลวตามที่ผู้สอนจัดทำไว้)
   ```
3. **สร้างระบบคุกคุมขังกลางสำหรับแบน IP (Jail Config):** [24]
   ```bash
   nano /etc/fail2ban/jail.local
   ```
   *คัดลอกค่าการกำหนดค่าการตรวจจับเหล่านี้ไปวาง โดยให้ละเว้น IP ส่วนตัวของผู้ดูแลระบบเพื่อป้องกันการแบนตัวเอง:* [24, 25]
   ```ini
   [DEFAULT]
   # ป้องกันไม่ให้แบนตัวเอง (ระบุ IP วงภายใน และ IP ของคอมพิวเตอร์หลัก)
   ignoreip = 127.0.0.1/8 [ระบุ IP ของเครื่องคุณ เช่น 10.100.13.31]

   [proxmox]
   enabled = true
   port = 8006
   filter = proxmox
   backend = systemd
   journalmatch = _SYSTEMD_UNIT=pvedaemon.service
   maxretry = 3
   findtime = 300
   bantime = 3600
   ```
4. **สั่งรันและเปิดการตั้งค่าให้เริ่มทำงานอัตโนมัติเมื่อบูตเครื่อง:** [26]
   ```bash
   systemctl enable fail2ban && systemctl restart fail2ban
   ```
5. **ตรวจสอบการทำงานและทดสอบสถานะการปิดกั้น IP:** [26, 27]
   ```bash
   # ดูสถานะภาพรวมและดูว่าคุก Proxmox ทำงานปกติหรือไม่
   fail2ban-client status proxmox
   
   # กรณีต้องการสั่งปลดแบน IP ที่ถูกบล็อกด้วยความผิดพลาด
   fail2ban-client set proxmox unbanip [IP_ADDRESS_ที่ถูกแบน]
   ```
